### Why Collins is not a fourth card

Two reasons, and the second matters more:

1. `.cards` in `site/site.css` is a hardcoded `repeat(3, minmax(0,1fr))` grid. A
   fourth article orphans onto a second row.
2. The three tiers are priced **per guest**; Collins is priced **flat per
   event**. Putting them in one row invites a comparison that does not hold —
   a reader mentally divides the flat fee by their headcount and gets a
   number that means nothing.

It is a separate section with its own `<h2>` and a lede that establishes
"flat fee, not per guest" before any figure appears.

## Pricing — banded by deployment size

Collins does not scale in guests, it scales in **stations**: roughly one station
per 25–30 guests, and one member of staff per two to three stations. A single
flat fee is therefore wrong above about 75 guests. The bands price the
deployment, not the head count — "flat fee per event, not per guest" still holds,
because the client still gets one number.

### Add-on — with Classic or Signature; **included with Reserve**

| Guests | Price |
|---|---|
| Up to 75 | **$950** |
| 76–150 | **$1,450** |
| 151–250 | **$1,950** |

Live in `config.js` as `variants` + `variantPrices` on the `collins` add-on, the
same shape the existing `photographer` add-on uses. No `quote-engine.js` change
was needed — the engine already resolves `variantPrices?.[variant]`.

### Standalone — "Collins on your bar", client pours their own

| Guests | Price | Stations / staff |
|---|---|---|
| Up to 75 | **$2,250** | 3 / 2 |
| 76–150 | **$3,250** | 5 / 3 |
| 151–250 | **$4,500** | 8 / 4 |
| 250+ | Custom quote | — |

Standalone extra hours band too: **$250 / $375 / $500** per hour. The site-wide
`extra-hours` rate is $500/hr, priced for a full bar with machines and
bartenders — applying that to a standalone Collins booking overcharges the two
lower bands. The top band lands on $500 anyway.

All bands are two-hour baseline, matching every other package. The 250 ceiling
matches `maxGuests` in config, so above it Collins inherits the existing
"custom quote" behaviour for free.

### The band is derived, not chosen

`collinsBand()` in `app.js` runs on every `setGuests` and when the add-on is
added. The existing variant pattern (`photographer`) is a user-facing dropdown,
which here would let someone quote a 150-guest event at the 75-guest rate.
Deriving the band from guest count removes that failure mode. If you add a
Collins variant selector to the UI later, keep the derivation as the source of
truth.

Verified boundaries: 75 → $950, 76 → $1,450, 150 → $1,450, 151 → $1,950;
Reserve $0 at every band.

**Included and stated as non-negotiable** (three iPads and stands, one to two
staff on site, the menu locked, branded interface, setup and breakdown). Naming
these is deliberate positioning: the NYC market's reputation is hidden fees —
competitors charge separately for real glassware and add 20% admin — so an
explicit inclusion list is a competitive weapon, not a giveaway.

**Do not sell this as "AI."** That premium is decaying fast; comparable AI
features are already sold as ~$49/week SaaS. Sell the operational bundle and
the thing the software actually does: Collins is held to the drinks the client
is pouring and will not recommend outside them.

## Open questions for the landing work

**Standalone has nowhere to live in the product.** The planner is package-first
— there is no path to buy Collins without a package. So all four standalone
prices, and the banded extra-hours, are page-and-proposal copy only, backed by
no `config.js` entry. That gap is now four prices wide. Decide whether standalone
is a real SKU or a "talk to us" line before it hardens into published pricing.
A config entry was deliberately not added, because it would put a line in the
estimate for a product the engine cannot sell.

**Reserve already promises "custom branding options"** (`site/reserve.html`),
which collides with Collins' branded-interface claim. `config.js` now resolves
this by listing "Collins interactive bartender included" as a Reserve feature
and setting `includedIn: ["reserve"]` — confirm that bundling is intended rather
than differentiating the wording.

**Copy is a draft.** In particular "no drink you did not agree to" is the
strongest line on the page and should be owned by whoever owns the brand voice.

## Blocker: the in-page Collins widget cannot be built yet

`events.barsys.com` resolves to `ghs.googlehosted.com` — a Cloud Run domain
mapping in project `happy-hour-landing-version-2` — which **bypasses the load
balancer entirely**. Consequently `/demo`, `/kiosk/*` and `/api/collins/*` all
return 404 publicly, and a widget on this site cannot reach Collins.

Unblocking it needs, in order:

1. An `INTERNET_FQDN_PORT` NEG in `barsyseliten` pointing at
   `barsys-happyhours-production-23nb3wybra-uk.a.run.app`. A serverless NEG
   cannot be used — it cannot reference a Cloud Run service in another project.
   The backend service **must** carry
   `--custom-request-header=Host:barsys-happyhours-production-23nb3wybra-uk.a.run.app`;
   without it the Cloud Run frontend 404s the original Host and the landing page
   goes down.
2. DNS: `CNAME ghs.googlehosted.com` → `A 136.68.142.9`, TTL 300.
3. `BARSYS_TRUSTED_PROXY_HOPS` 1 → 2 on `barsys-happyhours-production`, since
   the load balancer adds a hop and client-IP resolution shifts.

Already done: the URL map path rule was narrowed from `/api/*` to
`/api/collins/*` plus `/api/age*`. Before that change, routing this site through
the load balancer would have sent `/api/inquiries` and `/api/status` to Collins,
which has no such routes — silently destroying lead capture. That is disarmed.
